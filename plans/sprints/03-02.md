# Sprint 03-02: Game time, timers and speed controls

## Objective
Recreate the reference's time advancement and timed action semantics.

## V1 guardrail
Do not add new gameplay mechanics or rebalance the reference. Desktop usability and new graphics may differ, but gameplay rules must follow verified evidence. Any uncertain rule is logged as unknown rather than guessed.

## Task checklist
- [x] Document the reference's day/tick progression, pause behaviour, speed buttons, task durations, and timer rules from observed gameplay.

- [x] Game-time advancement matches documented reference behaviour (Normal: 1s/day, Fast: 0.5s/day, Ultra: 0.25s/day, Paused: 0s).
- [x] Render frame rate does not alter simulation results (verified across 60x 1s ticks vs 3600x 1/60s ticks producing identical state).
- [x] Pause and speed changes behave predictably and are covered by tests.
